# Практическая работа №6
## Создание автоматизированных Unit-тестов (Часть 1 и 2)

### 1. Цель работы
* Провести тестирование программных модулей с использованием средств автоматизации Microsoft Visual Studio методом "белого ящика".
* Реализовать документирование кода с помощью XML-комментариев.
* Разработать и выполнить набор тестов для проверки математических функций и бизнес-логики.

---

### 2. Описание тестируемых модулей

#### 2.1. Класс BankAccount (Часть 1)
Содержит логику управления банковским счетом:
* `Debit` — списание средств с проверкой на отрицательное значение и превышение лимита.
* `Credit` — зачисление средств с проверкой на положительный ввод.

#### 2.2. Класс MathLibrary (Часть 2)
Включает математические функции, перенесенные из ПР №4 (Abazov_323):
* `CalculateComplexExpression` — вычисление сложной формулы с проверкой деления на ноль.
* `CalculateConditional` — логика с ветвлением (sinh, sqr, exp).
* `CalculateTabulation` — расчет значений для таблицы/графика.

---

### 3. Документирование кода
Для всех методов добавлены XML-комментарии:
* `<summary>` — описание назначения метода.
* `<param>` — описание входных аргументов.
* `<returns>` — описание возвращаемого результата.

### 4. Реализация Unit-тестов
Всего реализовано более 16 тестов в проекте `TestProject1`.

#### Основные сценарии:
1. **Позитивные**: Проверка точности вычислений (Assert.AreEqual) для корректных данных.
2. **Негативные**: Проверка генерации исключений `ArgumentOutOfRangeException` при попытке деления на ноль или вводе отрицательных значений там, где это недопустимо.

---

### 5. Результаты тестирования
В ходе работы был проведен рефакторинг:
* Исправлена ошибка в методе `Debit` (замена сложения на вычитание).
* В `MathLibrary` типы исключений приведены к `ArgumentOutOfRangeException` для корректной обработки тестами.
